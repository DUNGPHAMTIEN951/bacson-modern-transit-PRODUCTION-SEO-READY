# PRODUCTION SEO READY Audit — Bắc Sơn Cường Nguyệt

Audit date: 2026-08-27

## Scope

This pass prepares the current single-page TanStack Start site for production SEO and a low-cost Cloudflare-oriented deployment. It does **not** promise search ranking and it does not invent business facts, reviews, ratings, schedules, fares, social profiles, certifications, or locations beyond the supplied project data.

## Changes completed

### Technical SEO

- Corrected the canonical URL from a non-existent route to `https://xebacsoncuongnguyet.com/`.
- Aligned `og:url`, Service schema IDs, breadcrumb schema, and the sitemap to the canonical root.
- Added a one-URL `public/sitemap.xml` matching the site’s actual route structure.
- Preserved `robots.txt` indexing and sitemap declaration.
- Added production OG/Twitter metadata, including image dimensions and image alt text.
- Added a self-hosted 1200×630 Open Graph image at `public/og-bac-son-cuong-nguyet.png` so social previews no longer depend on a Lovable preview URL.
- Cleaned LocalBusiness structured data: legal head-office address, contact points, visible-price range, services, FAQ, and a one-item breadcrumb matching the actual site architecture.
- Added `public/site.webmanifest`.
- Added `public/_headers` with conservative security/privacy headers and immutable cache rules for hashed build assets.
- Added a Vietnamese 404/error experience with `noindex,nofollow` metadata.
- Removed render-blocking Google Fonts and switched to a fast system font stack.
- Added preconnect for the current external photo asset origin.
- Added `scripts/verify-seo.mjs` plus `npm run seo:check` and `npm run verify`.

### Accessibility / UX / Core Web Vitals

- Kept exactly one H1 on the production landing page.
- Preserved skip-to-content, semantic sections, FAQ button state, explicit image dimensions, lazy loading for non-critical imagery, and high fetch priority for the hero image.
- Changed hero image decoding to asynchronous to reduce main-thread blocking.
- Fixed the mobile menu icon state (Menu ↔ Close).
- Strengthened focus-visible styling.
- Kept mobile sticky CTA spacing protected by the existing footer mobile padding.
- CTA contrast uses Signal Coral with Midnight Navy text (AA-safe); white-on-Navy and white-on-Ocean also exceed AA.

### Visual redesign

The old green/gold system was removed and replaced site-wide with:

- Midnight Navy `#0B1F33` — hero, trust sections, footer, dark surfaces.
- Ocean Blue `#1D4E89` — header, links, secondary emphasis.
- Signal Coral `#F06449` — high-attention CTA only.
- Coral Soft `#FFE7E0` — soft accent surface.
- Ice White `#F6F8FB` — alternating section background.
- Ink `#172033` and Slate `#334155` — text hierarchy.

Coral is deliberately not used as normal text on Ocean Blue because that pair does not meet WCAG AA contrast. Hero background therefore uses Midnight Navy when coral text is present.

## Important remaining dependency: photographic assets

The downloaded source archive contains Lovable pointer files (`src/assets/real/*.webp.asset.json`) rather than the 13 actual WebP binaries. To keep the site functional when deployed outside Lovable, `src/data/images.ts` now resolves those relative pointer URLs against:

`https://bacson-modern-transit.lovable.app`

This removes the **relative-path** deployment failure, but the photographs still depend on Lovable’s asset host. The production domain OG card is fully local.

Recommended final portability step: copy the 13 WebP binaries into a local static directory such as `public/images/`, update `src/data/images.ts` to `/images/...`, then remove `siteConfig.assetOrigin`. This could not be completed in this environment because the ZIP does not contain those binaries and the Lovable workspace ran out of agent credits before an asset export could be created.

## Business-content verification before launch

Code/SEO readiness is separate from factual business verification. The owner should confirm, immediately before launch:

- every departure time in `src/data/schedule.ts`;
- every fare and fare disclaimer in `src/data/fares.ts`;
- both phone numbers, Zalo number, office addresses, and legal/license data in `src/data/business.ts`;
- that the current external Lovable image host remains publicly reachable until the WebP files are self-hosted.

Do not add review stars, ratings, “best/number one” claims, unsupported service guarantees, fake locations, or keyword-doorway pages.

## Cloudflare deployment notes

The existing `vite.config.ts` uses `@lovable.dev/vite-tanstack-config`, whose project configuration targets Cloudflare/Nitro. No VPS is required for this site at the current architecture.

Run in a networked environment:

```bash
npm install
npm run verify
```

Then deploy the Cloudflare-compatible build output generated by the project. After the production domain is live:

1. Confirm `https://xebacsoncuongnguyet.com/` returns 200 and is the only canonical home URL.
2. Confirm `/robots.txt`, `/sitemap.xml`, `/site.webmanifest`, and `/og-bac-son-cuong-nguyet.png` return 200.
3. Confirm a random invalid URL returns a real 404 response and noindex metadata.
4. Inspect source HTML for canonical, description, OG/Twitter tags, and JSON-LD.
5. Test all phone and Zalo links on mobile.
6. Run Lighthouse/PageSpeed on mobile and desktop.
7. Add the domain property in Google Search Console and submit `/sitemap.xml`.
8. Ensure any Lovable preview/published duplicate is not promoted or indexed as a competing canonical site.

## Ranking disclaimer

“Production SEO ready” means the technical/on-page foundation is coherent, crawlable, canonicalized, accessible, and deployable. Google ranking depends on competition, relevance, content quality, local/business signals, links, user behavior, and time; no source-code change can guarantee a top position.
